# Testing

How we prove the system meets its requirements. Test code lives in the application, not here.

## What goes here

- `strategy.md` — test levels and what each covers, tools, environments, test data, coverage expectations

## What does not go here

- Test code, fixtures, snapshots → the application
- Acceptance criteria → [stories/](../stories/README.md)
- The traceability matrix → generated by CI and published as a build artifact and job summary; it is never committed, so it can never be stale

## Rules

- Tests reference requirement IDs: `@pytest.mark.req("US-001.AC1")` in the backend and `it("[US-001.AC1] ...")` or `test("[US-001.AC1] ...")` in the frontend. Several IDs are allowed: `req("US-001.AC1", "NFR-002")`, `it("[US-001.AC1, US-001.AC2] ...")`.
- Register the `req` marker in the pytest configuration so typos in marker names fail:

  ```toml
  [tool.pytest.ini_options]
  markers = ["req(*ids): requirement IDs verified by this test"]
  addopts = "--strict-markers"
  ```

- Run the [traceability check](../../tools/trace-check/README.md) locally before opening a PR.
