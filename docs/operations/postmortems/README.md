# Postmortems

Blameless analyses of incidents.

## What goes here

- Any incident that affected users, lost or exposed data, or required an emergency change
- Near misses worth learning from

## What does not go here

- The tracking of action items → GitHub issues, linked from the postmortem
- Bugs under investigation → [dev/investigations/](../../dev/README.md) until they become an incident

## Rules

- Write the draft within five working days of the incident, and review it with the people involved.
- Postmortems are dated and never rewritten after review. The file stem is the ID.

## Naming

`YYYY-MM-DD-slug.md`, dated by the day the incident started, e.g. `2026-10-25-login-outage.md`.
